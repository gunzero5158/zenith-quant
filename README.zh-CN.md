# 天台分析

[English](./README.md) | [简体中文](./README.zh-CN.md) | [日本語](./README.ja.md)

天台分析（英文名 **Rooftop Quant**，日文名 **屋上クオンツ**）是一个可自行部署的股票技术分析工作台，覆盖美股、港股、中国 A 股和日本股票市场。它在一个响应式仪表盘中整合多周期行情、结构化技术证据、交互式图表，以及两种可切换的评分与分析模式。

本工具仅基于公开行情、常规技术指标及 AI 提供分析参考，不构成投资建议或买卖指导。市场有风险，投资决策请独立判断并自行承担风险。

## 最近更新（2026 年 8 月）

- 新增分析模式切换：可选“规则评分 + AI”，也可选“纯 AI 分析”，让模型基于客观证据独立判断走势、入场质量、置信度和策略。
- 产品正式更名为 **天台分析**，英文名为 **Rooftop Quant**，日文名为 **屋上クオンツ**；页面同步加入多语言投资风险提示。
- 重构买点评估：左侧反转与右侧确认分别计算，但路径分数仅供内部使用；界面对外只展示一个最终综合分和清晰的情景状态。
- 神奇九转从第 6 阶段开始按进度逐步纳入形态成熟度，第 9 阶段权重最高；未走完九转也能作为证据，但不会被当作已确认信号。
- 分析历史新增上次分析时间；对应市场交易期间，缓存超过 10 分钟后再次点击会自动刷新行情并重新分析。
- 加固 AI 研报输出：修复 JSON 控制字符异常，阻止内部证据 ID 泄漏到可见文案，并保持策略内容与所选语言一致。
- 改进 A 股实时快照同步，使当前价格、指标和评分在支持的行情源上尽量使用一致的最新 K 线。

## 主要功能

- 搜索支持市场中的股票，并在浏览器中保存分析历史和行情快照。
- 在行情源可用时，基于真实市场数据构建日线和周线技术分析快照。
- 展示联动的价格与指标图层，支持日线/周线切换，以及红涨或绿涨配色。
- 同时支持“规则评分 + AI 复核”和基于同一客观证据快照的“纯 AI 自主评分”。
- 两种模式使用独立缓存，切换模式不会复用另一种模式的结论。
- 左侧和右侧情景显示为**未形成、观察、盘中暂定、确认、过晚**，对应的内部路径分数不对外展示。
- 分别生成行情概览、策略建议和技术细节三部分研报。
- 大模型生成失败且已开启兜底时，自动使用内置本地研报引擎。
- 实时行情源无法返回有效结果时，明确标记离线模拟数据。

## 分析范围

| 类别 | 分析内容 |
| --- | --- |
| 趋势与波动 | EMA、布林带、Ichimoku 一目均衡表、ATR、日线/周线结构 |
| 动量 | MACD、KDJ、RSI、近期交叉与背离 |
| 成交量与资金流 | 成交量均线、OBV、CMF、量价确认 |
| 价格位置 | 水平支撑/压力、斐波那契回撤、VPVR 价值区和主要筹码节点 |
| 结构与形态 | 经典图表形态、结合上下文的 K 线形态、TD Sequential 神奇九转 |
| 市场结构 | 艾略特波浪启发式分析，以及缠论分型、笔和中枢背景 |
| 决策辅助 | 入场情景、失效位、目标位、风险收益背景、数据质量评分上限 |

经典结构识别包括双顶/双底、三重顶/三重底、头肩形态、杯柄、圆弧结构、旗形、矩形、三角形、三角旗形和上升/下降楔形。形态结果只是分析证据，不能单独视为交易信号。

## AI 研报与评分

每次请求都会先构建相同的、不可变的客观技术证据快照，然后可选择两种模式：

- **规则评分 + AI**（默认）：本地引擎分别评估左侧反转和右侧确认路径，计算 0-5 分规则基础分；配置大模型后，AI 可基于证据在 `+/-0.5` 内复核调整。
- **纯 AI 分析**：模型只接收客观指标值、证据、价格层级和近期 K 线，不接收本地规则分、评分上限或预设趋势结论。模型在一次请求中独立输出走势、0-5 分、置信度、左右侧状态、风险方案和研报。

纯 AI 模式必须配置大模型，失败时不会暗中退回规则评分。止损和目标必须来自已提供的支撑压力层级；不完整或不合理的可执行方案会被降级为等待，但不会篡改 AI 给出的评分。

两条路径使用**未形成、观察、盘中暂定、确认、过晚**五种明确状态。路径的具体数字属于内部计算，不再作为额外评分对外展示。神奇九转从第 6 阶段开始提供有上限的衰竭证据，随后逐步增强至第 9 阶段；形成中的九转只是参考证据，不等于触发确认。

两种模式下，模型收到的都是结构化证据，不会被要求编造或重新计算指标，可见结论必须以已有证据为依据。最终研报分为：

- 市场与交易形态概览；
- 策略、触发条件和风险控制；
- 详细技术证据。

界面可选择 Google Gemini、OpenAI 和 Anthropic，也可以为 OpenAI 兼容服务填写自定义 Base URL。如果未配置大模型，或大模型请求失败且已启用本地兜底，仍可使用内置研报引擎。

## 快速开始

### 环境要求

- Node.js 20.9 或更高版本
- npm

### 安装与运行

```bash
git clone https://github.com/gunzero5158/zenith-quant.git
cd zenith-quant
npm install
npm run dev
```

打开 [http://localhost:3000](http://localhost:3000)。

生产环境构建：

```bash
npm run build
npm run start
```

## 配置

### 大语言模型

在应用中打开 **AI 设置**，填写：

- 服务提供商；
- 模型名称；
- API Key；
- 可选的 API Base URL；
- 是否启用本地研报兜底。

浏览器会在本地保存这些配置。执行分析时，凭据会发送到本应用的服务端接口，再转发至所选的大模型上游服务。本应用不会主动在服务端持久化保存大模型凭据。

默认禁止访问私有或内部的大模型地址。确实需要连接内网模型的自行部署环境可以显式开启：

```env
ZENITH_ALLOW_PRIVATE_LLM_HOSTS=true
```

### 可选行情源

创建 `.env.local` 可启用额外的兜底行情源：

```env
TWELVE_DATA_API_KEY=your_key
FMP_API_KEY=your_key
```

这两个密钥均为可选项。不配置时，应用仍会使用内置行情源链，但实际结果取决于上游服务是否可用。

## 隐私与限制

- 分析历史、缓存研报、显示偏好和大模型设置保存在浏览器存储或 Cookie 中。
- 行情和 AI 输出来自外部服务，可能存在延迟、缺失、不可用或错误。
- 出现演示模式提示时，当前结果使用的是模拟数据，而非实时行情。
- 本地缓存可以减少重复请求，也可以通过强制刷新发起新的分析。
- 技术指标、形态、评分和生成式研报只是概率性的决策辅助工具，不是价格预测或交易指令。
